# Демонстрация проекта (собеседование, ~5 минут)

Как показать этот проект так, чтобы он **работал**, а не «обычно работает».
Проверено прогонами 2026-08-17.

---

## 1. Preflight — за 10 минут до показа

Пять шагов, каждый отвечает «да/нет». Ни один не пропускать: все пять отказов
случались вживую.

```bash
# 1. Стек одной командой (ollama + backend 8000 + vite 5273). Ctrl+C гасит всё.
./scripts/dev.sh

# 2. Ассеты на месте (модели ~9 ГБ, голос, whisper)
curl -s http://127.0.0.1:11434/api/tags | grep -o 'qwen2.5:14b-instruct\|deepseek-r1:14b'
ls data/models/whisper/ggml-small.en.bin data/models/piper/en_US-hfc_male-medium.onnx
ls /opt/homebrew/bin/whisper-cli

# 3. Живой оракул полного цикла: настоящий Chromium, настоящий голосовой тракт.
#    Ожидаемый вердикт — closed-mid-turn (стенд намеренно рвёт ход посередине).
delivery/evals/browser/run.sh mid-turn

# 4. ГРЕТЬ МОДЕЛЬ. Первый ход на холодной ollama платит загрузкой ~9 ГБ и
#    выглядит как «зависло». Прогрев делает это невидимым.
curl -s http://127.0.0.1:11434/api/generate \
  -d '{"model":"qwen2.5:14b-instruct","prompt":"hi","stream":false,"options":{"num_predict":1}}' \
  -o /dev/null && echo "модель прогрета"

# 5. Наушники. НЕ колонки: микрофон открывается после конца воспроизведения, но
#    на колонках VAD слышит Генри — выглядит как «сам себя перебивает».
```

**Если что-то из 1–3 красное — не показывать вживую**, показать снимки
последнего прогона: `delivery/evals/browser/out/*.png`.

## 2. Сценарий показа

Порядок выбран так, чтобы «вау» случилось в первые тридцать секунд, а объяснения
шли **после** него.

| # | Что делаете | Что говорите / на что смотреть |
|---|---|---|
| 1 | Вкладка **Interview** → `Start interview` | Генри здоровается **голосом** и задаёт первый вопрос. Ничего не набрано, интернет не нужен |
| 2 | Отвечаете 20–30 секунд про свой проект | Пока говорите — орб «дышит»; замолчали на 2 с — уходит в `Thinking`. Первый звук ответа ≈ **1.3 с** |
| 3 | Слушаете follow-up | Вопрос **по вашему ответу**: нет цифры — спросит цифру; рассказ про людей — спросит про исход |
| 4 | Говорите: **«speak slower»** | Генри подтверждает и **дословно повторяет** прошлую реплику новым темпом. Это не запрос к модели, а детерминированный мета-ход: вопрос не потрачен |
| 5 | `End session` → `Skip for now` | Сессия закрыта, транскрипт сохранён |
| 6 | Вкладка **History** | Строка сессии: `начало → конец · длительность`. У брошенной было бы `not finished` |
| 7 | Вкладка **Useful Words** | Банк терминов с переводом и примером — набирается из разборов автоматически |
| 8 | Вкладка **Settings** → `Test` у микрофона | Полоска уровня с отметкой порога VAD: сразу видно, слышит ли вас агент |

Если время есть — шаг 5 сделать как `Review together`: Генри проходит ответы
вопрос за вопросом (Mode 2), после чего в фоне считается полный разбор на R1.

## 3. О чём рассказывать (числа настоящие, замеренные)

- **Всё локально.** whisper.cpp → qwen2.5:14b-instruct через ollama → Piper.
  Ни одного внешнего вызова: ни ключей, ни счетов, ни утечки транскриптов.
- **Почему по предложениям.** TTS запускается на первом же законченном
  предложении. Буферизация полного ответа замерена: 4.8 с против 3.0 с — гейт
  латентности проваливался. До первого звука сейчас ≈ 1.3 с при потолке 3 с.
- **Почему в диалоге не reasoning-модель.** `deepseek-r1:14b` замерен: 31–52 с на
  ход — на порядок больше бюджета. Он остался только на офлайн-разборе после
  сессии, где задержки не видно.
- **Структуру ведёт код, не модель.** Шесть вопросов чередуются
  технический/behavioral, follow-up решает детерминированная политика. Модель
  отвечает только за формулировки — поэтому сессия воспроизводима.
- **Запреты живут в рантайме.** Контракт режет фразу до озвучки; промпт — вторая
  линия. Модель может согласиться сказать лишнее — пользователь этого не услышит.
- **Дисциплина видна в цифрах.** 176 тестов бэкенда при 94.9% покрытия, 41 тест
  фронта, mypy strict, лимит 500 строк на файл — и всё это гоняется гейтами до
  коммита, а не «когда вспомню».

Если спросят «что было сложнее всего» — честный ответ: **эхо-защита**. Микрофон
можно открыть только после того, как реально стихли колонки; по событию «модель
закончила» или по таймеру — агент режет ход сам себе, и в тестах это не
воспроизводится.

## 4. Что может сломаться и что делать

| Симптом | Причина | Что делать при людях |
|---|---|---|
| Долгая тишина после первого вопроса | модель не прогрета | Сказать «подгружается модель, девять гигабайт» — это правда. Второй ход будет быстрым |
| Генри перебивает сам себя | звук идёт в колонки | Надеть наушники, начать сессию заново |
| Орб не уходит из `Listening` | микрофон тихий или не тот | Settings → `Test`: полоска ниже отметки — сменить вход |
| «Connection lost» | бэкенд упал или перезапустился | `./scripts/dev.sh` заново; транскрипт предыдущей сессии уже в базе |
| Пустая History | свежая база | Прогнать `run.sh mid-turn` до показа — появится сессия |

---

## 5. Чего в проекте нет (говорить самому, а не ждать вопроса)

- Один пользователь, без аутентификации и многопользовательности — это локальный
  инструмент, а не сервис.
- Нет мобильной версии и проверки на других браузерах: гоняется в Chromium.
- Смысловая верность перевода в банке слов машинно не проверяется — только
  алфавит (иероглифы и отсутствие кириллицы отвергаются).
- Полная сессия из шести вопросов автоматическим оракулом не покрыта: стенд
  проверяет ход и обрыв, остальное — человеком.
