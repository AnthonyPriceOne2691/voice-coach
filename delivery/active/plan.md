(тёмная база, градиентные пятна, стеклянные карточки, бирюза-синий акцент,

## Уроки архива, применимые к этому диффу (§2.2a)

Дифф трогает `frontend/src/**`, `backend/app/api/ws_voice.py`, `docs/17-*`,
`docs/15-*`, `delivery/evals/browser/`.

| Урок | Как применён здесь |
|---|---|
| **L17** — тест проверяет утверждение, прогон — вид | Главный урок поставки: у изменения, которое видно человеку, оракулом обязан быть **снимок**. Поэтому U1–U9 подтверждаются картинками, а не ассертами про смысл. Снимки «до» сняты ДО первой правки |
| **L16** — различимость состояний на экране | U9: орб обязан выглядеть по-разному в четырёх состояниях, и это проверяется четырьмя снимками, а не наличием CSS-класса |
| **L10** — ручной прогон находит невидимое сьюту | U12: живая сессия в браузере. Стенд уже умеет вкладки; сценарий расширяется съёмкой всех четырёх |
| **L11** — два файла, каждый со своей половиной канона | Doc 17 обещает маршруты (`/history`, `/settings`), а приложение живёт на табах без роутера. Расхождение чинится **в доке**, а не молчанием |
| **L3** — «зелёный гейт» и «гейт без половины» неразличимы | Фронтовые гейты живые с контура 2.01 (eslint-ратчет, complexity, jscpd, dependency-cruiser). Правка фронта — первая крупная с тех пор; гейты гоняются на каждом шаге, а не в конце |
| **L23/L33** — адрес важнее объёма; данные без политики вырождаются | Счётчик вопросов невозможно показать одним CSS: клиенту его сейчас **не присылают**. Значит либо трогать контракт WS, либо не обещать — выбрано первое, честно и с правкой doc 15 |
| **L13** — `.gitignore` под одно имя не ловит соседнее | Симлинк `frontend/node_modules` в worktree проверен `git status` |
| **L30/L32/L35** — гейты меряют не то, что называют | jscpd снят до правки; `okf_sync_gate` гоняется **после** коммита; eslint-ратчет сверяется до пуша |
| **L5–L9** — висы и разрывы | Не применимы: `useVoiceSession`, `audioQueue`, `vad` не трогаются вовсе (U11 это проверяет диффом) |

## Архитектура

### 1. Токены и слои — CSS без препроцессора

`styles.css` (314 строк) разбирается на три файла в `frontend/src/styles/`:

| Файл | Что держит |
|---|---|
| `tokens.css` | палитра, радиусы, тени, длительности переходов — **одно место правды** |
| `base.css` | сброс, фон-градиент, типографика, `.glass` как переиспользуемый слой |
| `app.css` | компоненты экранов |

Гейт длины файлов CSS **не** судит (маски `*.py *.ts *.tsx`), но разбиение
нужно не гейту: токены, лежащие среди правил, перестают быть источником правды.

**«Жидкое стекло» — это четыре свойства вместе**, а не одно `blur`:
полупрозрачная заливка градиентом сверху вниз, `backdrop-filter: blur+saturate`,
светлая грань `inset 0 1px 0` (край ловит свет) и мягкая тень наружу.

### 2. Компоненты

| Компонент | Судьба |
|---|---|
| `SessionStateRing` | → `StateOrb`: два размера (hero / compact), анимация по состоянию |
| `TranscriptPanel` | → диалог: пузыри, стороны, подпись ролью сверху |
| `MicLevelMeter` | остаётся, переодевается |
| `SessionHeader` | **новый**: состояние словами, счётчик вопросов, таймер, «End session» |
| `SettingsPage` | **новый**: темп речи ползунком, длительность, порог тишины |
| `App` | шапка «тихий бренд + табы», переключение с переходом |

Правило слоёв (`dependency-cruiser`) не меняется: `lib/` и `types/` — листья,
`hooks/` не тянет UI. Новые компоненты — обычные листья `components/`.

### 3. Счётчик вопросов: чего у клиента нет

Мокап обещает «Question 3 of 6 · behavioral». Этих данных во фронте **нет**:
сообщение `state` несёт только `value`, `session_kind`, `session_id`.

Решение: расширить payload `state` тремя полями — `question_index`,
`question_total`, `question_kind` — и обновить **doc 15**. Альтернатива (не
показывать) отброшена: знать, сколько осталось, снимает тревогу, а это и есть
задача тренажёра.

Таймер сессии клиент считает **сам** от `session_started` — бэкенду про это
знать незачем.

### 4. Settings

`GET /settings` → форма; `PATCH` на отпускании ползунка, не на каждом пикселе.
Валидация уже есть на бэкенде (422 вне коридора) — фронт показывает ошибку, а
не прячет её.

### 5. Что НЕ трогается

`hooks/useVoiceSession.ts`, `lib/audioQueue.ts`, `lib/vad.ts` — ни строкой.
Анимации живут в CSS и не имеют права стоить эхо-защиты и latency (U11).

## Границы и риски

- **Вкус гейтом не берётся.** Направление утверждено макетом до кода; итог
  проверяется снимками, и человек смотрит их на приёмке.
- **`backdrop-filter` на многих слоях** — расход GPU. На M5 незаметно, но
  число стеклянных слоёв держится в разумных пределах (шапка, карточки,
  пузыри — не каждый элемент).
- **`runtime_paths`: экран.** Отказ вёрстки платформа показывает пикселями, а
  не кодом ошибки. Значит нужен браузер, а не только `npm test`.
- **Дифф широкий по построению** — четыре экрана и полная смена стилей.
  Breaker'ы, скорее всего, потребуют подписи; разрез по экранам обсуждён в
  Rejected alternatives.

## Rejected alternatives

- **Только визуальный слой поверх текущей структуры** — отклонено, потому что
  половина проблем структурная: пустой транскрипт до старта и заголовок во всю
  ширину не лечатся градиентом.
- **Светлая тема** — отклонена человеком: потребовала бы второй палитры и
  своего макета, а ценность для одного пользователя за ноутбуком неясна.
- **`react-router` ради маршрутов из doc 17** — отклонено, потому что это новая
  зависимость ради адресной строки, которой в локальном инструменте никто не
  пользуется; расхождение с доком чинится правкой дока.
- **Tailwind или CSS-in-JS** — отклонено, потому что 1000 строк фронта не
  окупают сборочного слоя и новой зависимости; токены в CSS-переменных дают то
  же одно место правды.
- **Не показывать счётчик вопросов** (раз данных нет) — отклонено, потому что
  «сколько ещё» снимает тревогу, а цена — три поля в существующем сообщении.
- **Разрезать по экранам на три поставки** — отклонено, потому что общий слой
  (токены, стекло, шапка) правится один раз и всё равно задевает все экраны;
  разрез дал бы три окна наблюдения и два промежуточных состояния, где
  половина интерфейса в новом стиле, половина в старом.
- **Анимации на JS (framer-motion)** — отклонено: новая зависимость там, где
  хватает CSS-переходов, а лишний слой на пути к аудио-тракту не нужен.

Снимки «до» → токены и стекло → шапка и табы → Interview (до старта и сессия)
→ поле счётчика в WS + doc 15 → History → Words → Settings → doc 17 → снимки
«после» → живой прогон.
