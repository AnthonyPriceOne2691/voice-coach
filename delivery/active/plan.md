# Plan: темп речи по голосовой просьбе

Подтверждено человеком 2026-08-12: подтверждение + дословный повтор (без LLM);
темп переживает сессию; шаг ±0.15, коридор 0.85–1.60.

## Уроки архива, применимые к этому диффу (§2.2a)

Дифф трогает `backend/app/orchestrator/`, `backend/app/voice/`,
`backend/app/api/ws_voice.py`, `data/prompts/`, `docs/`, `knowledge/`.

| Урок | Как применён здесь |
|---|---|
| **L23** (`data/`, `orchestrator/`) — правка данных поведение не меняет, адрес важнее объёма | Прямо про эту поставку: темп — параметр **синтеза**, и никакая правка промпта его не сдвинет. Адрес — `PiperTts.synthesize`, а решение о мета-ходе — оркестратор. Промпты не трогаются вовсе, кроме четырёх новых реплик-подтверждений |
| **L24** (`data/contracts/`, `data/prompts/`) — поведение живёт там, где ЗАПРЕЩЕНО машиной | Проверено: реплика-подтверждение идёт **мимо** `TurnRunner` и енфорсера (как интро), значит контракт её не режет. Но проверено и обратное — что шаблоны подтверждений не содержат слов из `interview_forbidden.txt`; иначе Генри замолчал бы на границе |
| **L20/L22** (`data/knowledge/`) — «доехало до промпта» ≠ «используется» | Оракул P1 проверяет не наличие ключа, а **значение, с которым позван синтез**: `FakeTts` записывает `length_scale` каждого вызова |
| **L16/L17** (UI) — различимость состояний и снимок как оракул | Фронт в этой поставке не трогается сознательно (см. spec, Out of scope), поэтому браузерный оракул не требуется. Слышимое изменение проверяется живым прогоном (P8) |
| **L8** (`ws_voice.py`) — разрыв не отказ хода | Мета-ход добавляет ещё один путь отправки внутри `_run_turn`; он остаётся **внутри** существующего `try`, у которого `except WebSocketDisconnect: raise` стоит до широкого `except` |
| **L15** (гейт вечных жильцов) | Дифф трогает пути, связанные OKF-концептами (`orchestrator/`, `tts_piper.py`, `data/prompts/`) ⇒ sync-гейт сработает **обязательно**, и концепты правятся в этом же коммите, а не откладываются |
| **L25** (тест новой границы обязан задевать старое правило) | Сторож реплик подтверждения проверен **с красной стороны**: enforcer получает «Sure, slowing down. I'd rate that answer four out of 5.» и обязан её зарезать. Без этой строки сторож был бы зелёным при любом контракте |
| **L5**, **L6**, **L7**, **L9** (`ws_voice.py`, висы и разрывы) | Прямо в прогоне: тест P7 сначала выходил из `with` при живой сессии и оставлял `no active connection` в логе — та же форма, что годовой вис. Исправлено дослушиванием `session_ended`, а не подавлением. Мета-ход при этом **не создаёт задач** и не трогает `_warmup_task`, поэтому нового источника висов не вносит |
| **L10** (ручной прогон находит то, чего не видит сьют) | Причина, по которой P8 объявлен живым замером, а не оценкой: слышимость темпа `FakeTts` подтвердить не может в принципе |
| **L1** (`CI` ≠ `quality`, «красный CI» — не одно состояние) | В verify-report фиксируются оба workflow поимённо, а не «CI зелёный» |
| **L26** (снятый инвариант зачёркивают, а не стирают) | Не применим: поставка ничего не снимает — только добавляет мета-ход и параметр темпа |
| **L27** (формальное срабатывание sync-гейта полезно) | Подтвердилось: гейт указал на `transcript-durability` — и там действительно не хватало правила о том, что мета-ход тоже флашится, а отбрасывает его **читатель**, не писатель |

## Архитектура

Три новых куска и один сдвинутый шов.

### 1. Политика — `backend/app/orchestrator/pace.py` (новый, чистый)

Ровно та же природа, что follow-up-политика в `interview.py`: детерминированное
решение без модели, тестируемое таблицей.

```
PaceRequest = SLOWER | FASTER
detect(text) -> PaceRequest | None        # None = обычный ответ
apply(current, request) -> (new_scale, at_limit: bool)
```

Два правила распознавания, оба нужны:
- **фраза из таблицы** (`slower`, `too fast`, `slow down`, `speak faster`, …);
- **и реплика короткая** — не длиннее `MAX_REQUEST_WORDS = 12` слов.

Второе правило — то, что отделяет P1 от P4. Без него ответ «we had to speed up
the pipeline…» стал бы мета-ходом и съел бы содержательную реплику: цена ложного
срабатывания здесь выше цены пропуска (§4.3b), поэтому порог смещён в сторону
«скорее обычный ответ».

### 2. Носитель темпа — `backend/app/voice/tts_paced.py` (новый)

`TextToSpeech` получает необязательный `length_scale` (шов расширяется, а не
ломается: у всех существующих вызовов поведение прежнее). `PacedTts` — тонкий
адаптер вокруг `PiperTts` с **изменяемым** текущим темпом.

Почему адаптер, а не параметр через все вызовы: синтез зовут из четырёх мест, и
`TurnRunner` — одно из них. Протаскивать темп через сигнатуру `run()` значит
дать раннеру знание, которым он не владеет; адаптер оставляет его нетронутым.

Экземпляр — **на сессию** (в `_SessionHandler`), не на приложение: темп одной
сессии не должен утекать в параллельную. `container.tts` остаётся общим Piper'ом
с загруженной моделью — модель по-прежнему грузится один раз (doc 19 note 4).

### 3. Мета-ход — `ws_voice._run_turn`

```
text = STT(...)
if (request := detect(text)) is not None:   -> _handle_pace_request(...) -> return
plan = await flow.on_user(text)              # прежний путь, не тронут
```

`_handle_pace_request`:
1. `new, at_limit = apply(self._tts.scale, request)`;
2. `self._tts.set_scale(new)` — **до** синтеза, поэтому подтверждение уже звучит
   новым темпом (это и есть проверяемая часть P1);
3. `user_settings.update({"speech_length_scale": new})` — переживание сессии;
4. озвучить `template(...)` + **дословно** последнюю реплику агента;
5. записать оба хода в транскрипт как мета и **не** трогать ни оркестратор,
   ни историю LLM.

**История LLM не пополняется сознательно.** Модель не должна видеть ни просьбы,
ни повтора: её контекст остаётся ровно таким, каким был до просьбы, иначе в
истории появится дубль вопроса, а doc 20 считает бюджет токенов.

### 4. Хранение и REST

- `speech_length_scale` — четвёртый ключ `DEFAULTS`; дефолт приходит **из
  конфига** (`Settings.piper_length_scale`) через новый параметр конструктора
  репозитория, а не вторым литералом 1.15 в другом файле;
- `PATCH /settings` начинает **валидировать** этот ключ: вне коридора → 422.
  Молчаливый зажим отвергнут в спеке (P6) как неотличимый от принятого значения;
- мета-ходы исключаются из `_render_transcript` в `summary/service.py` — иначе
  просьба о темпе уедет в промпт R1 как реплика кандидата (P9).

## Границы и риски

- **Latency.** Мета-ход **не** зовёт LLM, поэтому он заведомо быстрее обычного.
  Риск в другом: обычный ход на `1.60` синтезирует первое предложение дольше.
  Оценка — доли десятой секунды (hfc_male ~0.12 s/предложение на 1.0), но
  оценка решением не является: P8 требует живого замера.
- **`runtime_paths`.** Слышимость темпа — путь, чей отказ не виден ни сборке, ни
  тестам: `FakeTts` радостно запишет любое число. Значит нужен прогон живым
  Piper'ом с ушами, и он объявлен в STATUS.
- **Ослышки STT.** `whisper small.en` путает `slower`/`lower`. Ограничитель тот
  же — короткая реплика; отдельного лечения нет и не обещается.

## Rejected alternatives

- **Определять просьбу моделью** (классификатор в промпте) — отклонено, потому что
  «ответ это или обращение к инструменту» есть структура, а структурой владеет код
  (I1-H6); плюс невоспроизводимость в тестах и лишний вызов LLM на каждом ходе.
- **Дать LLM переформулировать вопрос новым темпом** — предъявлено человеку и
  отклонено им, потому что добавляет полный вызов модели (~1.5–2 s) и прогон через
  енфорсер там, где нужен дословный повтор: просьба «медленнее» означает «я не
  расслышал», а не «объясни иначе».
- **Темп только на сессию, без хранения** — отклонено человеком, потому что просить
  пришлось бы каждый раз; хранение заодно даёт готовую точку подключения регулятора
  в будущем UI.
- **Молча зажимать значение в `PATCH /settings`** — отклонено, потому что 200 на
  неприменённую настройку неотличим от успеха; 422 дороже на одну ветку, но честно (P6).
- **Протащить темп параметром через `TurnRunner.run()`** — отклонено, потому что дало
  бы раннеру знание, которым он не владеет, и расширило бы сигнатуру ради одного места
  вызова; адаптер `PacedTts` оставляет раннер нетронутым.
- **Мутировать `length_scale` прямо в общем `PiperTts`** — отклонено, потому что темп
  одной сессии утёк бы в параллельную, а обёртка на сессию стоит 12 строк.
- **Хранить таблицу формулировок в `data/`** — отклонено, потому что `data/` в этом
  проекте есть то, что читает модель (промпты, контракты, вопросы), а таблица
  распознавания — политика, и её место рядом с политикой follow-up в коде. Цена
  решения: новая формулировка требует правки `.py`, а не текстового файла.
- **Отдельный тип WS-сообщения для смены темпа** — отклонено, потому что потребовал бы
  клиента, который умеет его слать, то есть UI; голосовой путь работает уже сейчас и
  не трогает фронт.

## Порядок (vertical slice, §5.3)

Политика с тестами → шов TTS с тестами → мета-ход в ws_voice → хранение/REST →
docs+OKF → живой замер. Каждый шаг оставляет дерево зелёным.
