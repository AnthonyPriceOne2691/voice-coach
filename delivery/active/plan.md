# Plan: выразительная речь

Подтверждено человеком 2026-08-13: вариант D спайка (интонация + ритм + паузы,
тот же голос); пауза перед каждым чанком кроме первого; параметры — в конфиге,
не в REST.

## Архитектура

### 1. Интонация и ритм — параметры синтеза

`Settings` получает `piper_noise_scale: float = 0.667` и
`piper_noise_w: float = 1.0`. `PiperTts` принимает их в конструкторе и кладёт в
`SynthesisConfig` рядом с `length_scale`.

Почему не per-call, как темп: темп пользователь меняет голосом на лету (мета-ход),
а интонация — **характер голоса**, он один на процесс. Класть его на шов
`TextToSpeech` значило бы объявить изменяемым то, что не меняется.

### 2. Дыхание — тишина перед чанком

Новый чистый модуль `backend/app/voice/prosody.py`:

```
lead_in(wav: bytes, seconds: float) -> bytes   # тишина ПЕРЕД звуком, формат тот же
```

Вставка — в `_send_audio` (`ws_voice`), по счётчику чанков хода:

```
первый непустой чанк очереди -> как есть
последующие                  -> lead_in(wav, SENTENCE_PAUSE)
final=True                   -> счётчик сброшен
```

Почему именно там, а не в `TurnRunner`: одним местом закрываются **все** пути,
где подряд идут несколько реплик, — ход интервью, подтверждение темпа с
повтором, разбор в Mode 2. В `TurnRunner` пришлось бы дублировать, а два места
разъезжаются (это ровно L11).

Почему **перед**, а не после: пауза после последнего предложения — это задержка
перед открытием микрофона, то есть плата на каждом ходе за красоту, которой
никто не услышит. Решение человека.

### 3. Фронт не трогается

Пауза приезжает в самих байтах, `AudioQueue` продолжает ставить чанки встык и
ничего не знает о просодии. Это и есть причина, по которой поставке не нужен
браузерный оракул.

## Границы и риски

- **Latency**: замер спайка — 41 ms на первое предложение против 40 ms сейчас.
  Тишина добавляется только со второго чанка, то есть на путь до **первого**
  звука не влияет вовсе. Перезамер живым стеком всё равно обязателен (E6).
- **`runtime_paths`:** `backend/app/voice/tts_piper.py` — слышимость платформа
  подтверждает звуком, а не кодом ошибки; тест увидит нужное число сэмплов и
  останется зелёным при любом качестве звучания.
- **Транскрипт не затронут**: пауза живёт в аудио, в тексте её нет.

## Rejected alternatives

- **Сменить голос на `ryan-high`** — предъявлен человеку образцом и отклонён,
  потому что выразительности удалось добиться на текущем голосе за 41 ms, а
  смена стоила бы 225 ms и сделала бы Генри другим человеком.
- **Пауза в `AudioQueue` на фронте** — отклонено, потому что потребовало бы
  правки фронта и браузерной приёмки ради того, что дешевле сделать в байтах;
  плюс клиент перестал бы быть глупым.
- **Пауза после каждого предложения** — отклонено человеком, потому что
  добавляет 0.35 s ожидания перед открытием микрофона на КАЖДОМ ходе.
- **Пауза внутри `TurnRunner`** — отклонено, потому что не покрывает подтверждение
  темпа и Mode 2, а второе место вставки разъедется с первым (L11).
- **`noise_scale` и паузу — в `GET/PATCH /settings`** — отклонено человеком:
  это характер голоса, а не предпочтение на каждый день; код и тесты ради
  однократной настройки не окупаются.
- **Разметка пауз по пунктуации** (запятая короче точки) — отложено: сначала
  надо услышать, мешает ли ровность одинаковой паузы.
- **«Говори выразительнее» в промпте** — не рассматривалось всерьёз: просодия
  задаётся синтезом, текст на неё не влияет (L23).

## Порядок (vertical slice, §5.3)

Параметры синтеза с тестом → `prosody.py` с тестом → вставка в `_send_audio` →
docs+OKF → живой перезамер (E6) → слушание человеком (E7).
