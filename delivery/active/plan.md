# Plan: заметки разговора — Language notes, Listen, Add to Useful Words, History (talk-notes, D3a.2 — 2 из 3)

## Approach

**Заметки только читаются.** Их пишет проверка речи (talk-check, ведущая сессия) в
`talk_sessions.metadata_json["language_notes"]` по контракту из `spec.md`. Эта
поставка их отдаёт, показывает, озвучивает и кладёт в банк слов — и ни одного
решения «что считать заметкой» не принимает. Тесты создают строки разговора с
такими метаданными напрямую, без проверки речи.

**REST — свой модуль `api/routes_talks.py`.** `ws_voice.py` не трогается.

| Эндпоинт | Что |
|---|---|
| `GET /sessions/talks?limit&offset` | страница разговоров, новые первыми; `limit` 1…100 (гейт unbounded-list) |
| `GET /sessions/talks/{id}` | разговор + транскрипт + `language_notes` |
| `POST /sessions/talks/{id}/notes/{n}/vocabulary` | фраза `better` → Useful Words |
| `GET /sessions/talks/{id}/notes/{n}/audio` | WAV фразы `better` темпом пользователя |

**Длительность разговора — из `ended_at − started_at`.** В метаданных разговора
`duration_sec` нет (у интервью он пишется оркестратором). У разговора без
`ended_at` длительность `null`, и History ставит «not finished» по `ended_at`, как у
интервью (L16).

**Add to Useful Words (C12):**
1. термин уже в банке (без регистра, как dedup doc 10) — ответ `exists`, модель не
   зовётся, `times_seen` не растёт: повторный клик — не «встретилось снова»;
2. термин в банке, но удалён человеком — запись возвращается (`added`): правило
   doc 10 «удалённое не добавлять» защищает от экстрактора, а не от явной просьбы;
3. иначе перевод на qwen тем же `SummaryService.translate_term`, что чинит банк
   (L57: не на R1). Usage — фраза Антона с уже исправленным фрагментом. Перевод
   судит S-H6 (`translation_problem`): негодный — 502 и ничего не записано; модель
   недоступна — тоже 502. Запись — через `VocabularyRepository.merge`;
   `type` — `word` или `phrase` по числу слов, `category` — `fluency` (doc 10:
   разговорная беглость, не архитектура и не импакт), `context_note_en` —
   «You said: “…” — причина».

**Listen (C11).** Темп — тот же коридор, что у голосовой сессии: сохранённый
`speech_length_scale`, если он число в коридоре, иначе `Settings.piper_length_scale`.
Синтез получает темп явным аргументом КАЖДОГО вызова (L29).

**Экран.** `components/LanguageNotes.tsx` — список «you said → better — why» с
кнопками Listen и Add to Useful Words (added / already there / error) и честным
пустым состоянием; оценок нет. TalkPage после конца разговора берёт заметки по
`session_ended.session_id`. History получает раздел Talks: строки (дата,
длительность или «not finished», число заметок) и деталь (заметки + транскрипт
через `TranscriptView`). Голова строки History вынесена общей для интервью и
разговора — иначе вторая копия (jscpd, база 0 клон-пар). Стили — новым файлом
`styles/notes.css` (L42).

## Rejected alternatives

- **Добавлять в банк одним `merge` без проверки наличия** — отклонено, потому что
  `merge` на существующем термине поднимает `times_seen`, а удалённый пропускает
  молча: экран сказал бы «уже там» про слово, которого в Useful Words не видно.
- **Перевод на R1** — отклонено, потому что D-8 и L57: R1 — источник утечки CJK в
  переводах, починку он и вызвал.
- **Один хронологический список интервью и разговоров** — отклонено, потому что две
  постраничные выборки, слитые в одну, обрезают одну из них произвольно, а у строки
  интервью действия, которых у разговора нет (Review, Delete).
- **Звук через WS** — отклонено, потому что после конца разговора сессии нет, а
  `GET` с WAV проигрывается браузером штатно (`new Audio(url)`).
- **Заметки в пузырях транскрипта** — отклонено, потому что спека просит список
  «you said → better» с кнопками, а пузыри — дословная запись разговора.

## Risks

- **Контракт с параллельной talk-check** — читаются только поля контракта; заметка
  без строк `said`/`better` — нарушение контракта: она пропускается с записью в лог,
  а не роняет экран.
- **Перевод ФРАЗ — новый класс входа** для промпта, написанного под термин (L33,
  L76). S-H6 отвечает «не мусор ли», а не «хорошо ли» (L58): качество перевода фраз
  проверяет человек на живой модели по «запускай»; в сигнале наблюдения — доля
  отвергнутых.
- **Предохранитель 800 строк** с тестами и доками (L77): мерить собранную ветку до
  разговора о разрезе.
- **jscpd** — строка и деталь разговора повторяют голову строки интервью; общая
  часть выносится до коммита, замер обеих половин до и после (L30).

## Уроки архива по затронутым путям (§2.2a)

- **L3, L4** — TS-половины гейтов живые: ESLint warning-ратчет прежний (1); база диффа
  у оракулов — `origin/main`.
- **L5, L6, L7** — `main.py` тронут только регистрацией роутера; lifespan и уборка ws
  не меняются; `delivery_check` гоняется руками с `--diff-base origin/main`.
- **L11, L12, L13, L14, L15** — новые адреса живут под `/sessions`, прокси его уже
  покрывает; сторож «префиксы `api.ts` ⊆ `server.proxy`» прогоняется; venv и
  node_modules — свои каталоги, коммит по явным путям.
- **L16, L17** — у разговора закрытый и брошенный различимы на экране по `ended_at`;
  строки интерфейса английские; вид проверяется снимком, а не только assert.
- **L28, L29, L30, L31, L32** — темп Listen — значение каждого вызова синтеза
  (`FakeTts.scales`); jscpd до и после; покрытие диффа гоняется отдельно от
  `run_checks`, `coverage.json` в коммит не попадает.
- **L33, L34, L35, L36** — перевод фразы — новый класс данных для промпта термина;
  OKF-гейт гоняется после коммита, не до.
- **L41, L42, L43, L44, L45, L46** — новый слой интерфейса отдельными файлами, общий
  слой не переопределяется; данные для экрана есть в API до вёрстки (`session_id` в
  `session_ended`, `language_notes` в детали).
- **L47, L48, L49, L50, L50a** — компонентные тесты на jsdom с явным `cleanup()`;
  новых зависимостей нет.
- **L51, L52, L53, L54** — микрофон не трогается; `runtime_paths` пересмотрен:
  REST и экран исполняют тесты.
- **L55, L56, L57, L58, L59** — перевод судит S-H6, перевод делает qwen, качество
  фраз — человек; `summary/**` не трогается, OKF-концепт model-split не задет.
- **L60, L61, L62** — модель в тестах управляемая (`ScriptedLlm`, падающий двойник);
  каждый новый сторож проходит мутацию в той же сессии.
- **L69, L70** — `rule_enforcers.md`: строка S-H6 у промпта перевода называет и новый
  вызов; живая база человека не трогается — стенд, если он будет, на своей базе.
- **L77, L79** — предохранитель меряется на собранной ветке; коммиты по слоям без
  stash.
- **L80, L81** — не применимы: прогрева и замера латентности в поставке нет; Listen
  латентностным гейтом не мерится.
