# Tasks: у каждого ключа настроек есть читатель

## Mini-spec (класс S, §2.2)

**Проблема.** Два дефекта одного класса подряд: `silence_threshold_ms` и
`show_live_transcript` с 2026-08-13 хранились, отдавались и показывались на
экране Settings, но не читались ничем, что меняет поведение. Сторож связки
(`useVoiceSession.test.tsx`) стоял только на `mic_device_id`.

**Что должно быть правдой:**

| id | Вход | Ожидаемое |
|---|---|---|
| K1 | каждый ключ `DEFAULTS` на текущем `main` | у каждого есть читатель вне экрана Settings, объявления, хранилища и маршрута — тест зелёный |
| K2 | хук и экран интервью из `55625ed` (до правок 2026-10-01) | красные ровно `show_live_transcript` и `silence_threshold_ms`, в сообщении — имя ключа |
| K3 | ключ упомянут только в комментарии | читателем не считается: комментарии вырезаются до поиска |
| K4 | файл из списка исключений переименован или удалён | красный тест: список исключений протух |
| K5 | ключ законно только показывается | вносится в `DISPLAY_ONLY` с причиной; запись для несуществующего ключа — красный тест |

**Out of scope.** Правильность применения значения читателем — это проверяют
тесты самих читателей и стенд (`run.sh silence`). Тест ловит «читателя нет вовсе».
