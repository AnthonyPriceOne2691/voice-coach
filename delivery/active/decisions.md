# Decisions: soft-skills

Одна строка на выбор (§12.2). Отклонённые варианты с причинами — `plan.md`.

| # | Решение | Кто | Почему |
|---|---|---|---|
| D1 | Чередование классов в одной сессии вместо отдельного режима | human:anthony | Настоящее интервью смешивает вопросы, и тренировать надо **переключение**; отдельный режим потребовал бы селектора во фронте и браузерной приёмки |
| D2 | Три behavioral из шести | human:anthony | Половина сессии сохраняет техническую глубину; при трёх и трёх чередование выходит ровным (T,S,T,S,T,S) без остатка |
| D3 | Своя ветка признака слабого ответа для behavioral | human:anthony | «Нет цифр» у рассказа о людях истинно почти всегда — одно правило на оба класса вырождается в «допрашивать всегда» и выглядит придиркой к хорошим ответам |
| D4 | Признак behavioral = эпизод **и** исход | agent | Это и есть разница между историей и декларацией («I always try to communicate clearly»). Требовать только эпизод — пропустить историю без финала, а именно финал интервьюер и спрашивает |
| D5 | Признаки — словари в коде, не модель | agent | Та же природа, что таблица формулировок в `pace.py`: цена ошибки низкая в обе стороны, а воспроизводимость нужна тестам |
| D6 | Шаблон `\w+ed` в `_EPISODE` **не** добавлен | agent | Ловил бы `speed`, `need`, `red` и систематически завышал бы силу ответа — то есть отнимал бы допрос там, где он нужен |
| D7 | Класс задаёт ключ `kind:` **файла** банка | agent | Банк и есть класс; восемь одинаковых полей рассинхронизируются раньше, чем понадобится смешанный файл |
| D8 | Неизвестный `kind` роняет загрузку | agent | Опечатка, молча ставшая `technical`, — это дефект, который никто не заметит: вопросы будут задаваться, а политика окажется не та |
| D9 | Чередование детерминированное, случаен только выбор внутри класса | agent | Случайные «3 из 6» регулярно дают три soft подряд, и сессия перестаёт тренировать переключение — то самое, ради чего классы смешаны |
| D10 | `pick_session_pool` принимает два списка, а не флаг | agent | «Сколько soft» — решение оркестратора, и оно должно быть видно в сигнатуре, а не спрятано в параметре-числе |
| D11 | Своя инструкция и свой seed для behavioral follow-up | agent | У рассказа о людях другие дыры: спрашивать про trade-off и измеримый эффект здесь мимо. Подтверждено живым прогоном — ход 4 спросил про объяснение человеку |
| D12 | `question_kind` пишется в транскрипт | agent | Банк — данные, они меняются; по одному `question_id` через полгода уже не сказать, каким был вопрос. Транскрипт — невосполнимый артефакт |
| D13 | `ReviewPlan` получил поле со значением `None` | agent | Ход Mode 2 своего класса не имеет; поле есть ради общей записи в `SessionFlow`, и `None` это честно называет. Альтернатива — `getattr` с умолчанием, то есть та же связь, но невидимая типам |
| D14 | `interview_mode` = `technical_and_behavioral` | agent | Сессия перестала быть чисто технической, и запись обязана это называть. Старые строки остаются с прежним значением — они описывают другую сессию |
| D15 | Фронт не трогается | human:anthony (через спеку) | Значение `interview_mode` доезжает до типа, но не рендерится; селектора режима нет по D1 |
| D16 | Порог 40 слов не пересматривался | agent | Для behavioral он значит не то же, что для технического, но данных, что он мешает, нет. Менять без замера — гадание; записано в «чего проверка не покрывает» |
