# Spec: строгий рантайм сьюта — `filterwarnings = ["error"]` и утечки соединений (test-leaks)

## Problem

Канон держит `filterwarnings = ["error"]` с `cqg@1.13`: любое предупреждение в тесте —
красный тест, потому что «предупреждение, которое никто не читает, — это баг с
отложенным сроком». В этом проекте строки не было никогда. Накат 2.69 (18.10) снял
замер и отложил порт отдельной поставкой («Остатки обновления 2.69» в
`delivery/STACK-ACCEPTANCE.md`):

1. сбор тестов падает в 7 модулях на `StarletteDeprecationWarning` — импорт
   `starlette.testclient` с `httpx` вместо `httpx2`; канон документирует для этого
   одну строку ignore;
2. после неё 8–9 из 272 тестов падают **недетерминированно** на
   `PytestUnraisableExceptionWarning` из `aiosqlite` `Connection.__del__` —
   незакрытые соединения.

Замер этой поставки (2026-10-23, `diagnosis.md`): соединения оставляют открытыми
**18 тестов**, а падают **5 других** — среди них `test_tts_piper.py`, который базы не
касается. Набор упавших меняется от включения coverage. Красный прогон указывает не
на виноватого, а на того, в чьём тесте сработал сборщик мусора.

Это тот же класс, что подвешивал прогон в августе (L5–L7): соединение вне пула,
которое добивает сборщик мусора. Тогда это был вис целиком, сейчас — случайно
красный тест.

## Users / stakeholders

Антон — как читатель CI и как разработчик: красный тест обязан указывать на тест,
который сделал дефект, а зелёный — означать, что предупреждений не было. Будущие
поставки — им строгий режим и сторож достаются даром.

## In scope

- `filterwarnings = ["error"]` в `backend/pyproject.toml` и ровно одна строка ignore
  из канона (starlette/httpx) с причиной в комментарии.
- Починка корней: у каждого движка, который создаёт тест, фикстура или помощник,
  есть владелец, который его гасит (`dispose()`), в том числе при исключении.
- Детерминированный сторож: autouse-фикстура, которая в конце КАЖДОГО теста
  утверждает, что всё открытое закрыто и всё выданное пулом возвращено, — независимо
  от момента сборки мусора. Доказан мутациями.
- Тесты самого сторожа: каждая форма утечки называется, чистая работа — тишина.
- Записи контура: `scripts/lint/adapted.json` (`backend/pyproject.toml`) и строка
  `filterwarnings` в «Остатках обновления 2.69».

## Out of scope

- **Продуктовые пути гашения приложения.** Сторож нашёл там две скрытые утечки —
  `SummaryService.aclose()` отменяет задачи без ожидания, `_drain` в `main.py` по
  сроку не отменяет уборку вовсе (`diagnosis.md`, H5). Сьют их не исполняет, в
  жизни окно — миллисекунды. Правка `summary/service.py` задевает концепт
  `model-split` и требует `canon_drift_waiver` с подписью человека, а у waiver'а
  `deferred` не бывает (Delivery §3.4: «Человека нет — waiver'а нет», законный выход
  — разрезать поставку). Repro и проверенная правка переданы следующей поставке.
- Переход тест-клиента на `httpx2` — новая зависимость, решение человека.
- `scripts/repair_vocabulary.py` не гасит свой движок: процесс выходит, на выходе —
  `ResourceWarning`. Разовый скрипт без тестов; записано, не тронуто.
- `PYTHONDEVMODE` / `pytest-env` из того же блока канона.

## Acceptance (observable)

- [ ] `filterwarnings = ["error"]` стоит, ignore — одна строка канона с причиной
- [ ] 10 полных прогонов сьюта подряд (с coverage) — 0 красных, на macOS и в
      linux-контейнере с Python 3.12
- [ ] сторож краснит тест-виновника на каждом прогоне, а не случайный чужой
- [ ] покрытие не ниже гейта 85%; `quality` и `CI` в GitHub Actions зелёные
