# Spec: Генри знает всё портфолио, а не один проект

## Задача

В системный промпт инжектится только `profile_condensed.md`. В нём LinkBuilder
и упоминание Event Content System — остальные четыре проекта агенту невидимы.
Интервьюер, который знает один проект из пяти, не может ни выбрать, что копать,
ни поймать несогласованность с CV.

## Инвариант

**Профиль агента говорит правду о системах, а не повторяет CV.** Решение
человека 2026-08-12: цифры берутся из ЗАМЕРА по репозиториям, с датой замера.
Там, где CV расходится с замером, прав замер — а расхождение становится
списком правок для CV, который отдаётся человеку.

Следствие, которое надо принять осознанно: Генри может спросить про цифру,
которой в текущем CV нет. Это выбрано намеренно — кандидат обязан уметь
защитить реальные числа своих систем, а CV подтягивается к ним, не наоборот.

## Что меняется

1. `data/knowledge/profile_condensed.md` переписывается: позиционирование,
   сигнатурный сюжет «LLM под контрактом — один паттерн, четыре системы»,
   **индекс всех пяти проектов** с измеренными цифрами, правила позиционирования,
   слабые места. Потолок — **1500 токенов** (doc 20).
2. `data/knowledge/ANTON_ASPIDOV_CV_EN.md` обновляется копией от 2026-08-11
   (в знании лежит версия от 2026-07-02).
3. `docs/05-knowledge-base.md`: таблица источников пополняется, фиксируется
   решение «индекс в профиле, глубокие кейсы — за оркестратором».
4. Тест на бюджет: профиль обязан влезать в объявленный потолок, иначе
   `num_ctx` съедается молча.

## Что НЕ меняется

- **Оркестратор и промпты хода.** Выбор проекта для вопроса — его работа
  (I1-H6), и она в отдельной поставке.
- Слот `case study ≤ 1000` остаётся пустым: некому решать, чей кейс подставить.
- Механика инжекта `{{profile_condensed}}` — код не трогается.
- CV сам не правится этой поставкой: список расхождений отдаётся человеку.

## Acceptance examples

| # | Вход | Ожидаемый выход |
|---|---|---|
| F1 | `profile_condensed.md` после правки | Содержит все пять проектов поимённо: LinkBuilder, Voice Interview Coach, Local Web Agent, Lash Try-On, Event Content System |
| F2 | Замер размера профиля | ≤ 1500 токенов по оценке doc 20 (граничный случай: превышение съедает `num_ctx` молча, поэтому проверяется тестом, а не глазом) |
| F3 | У каждого проекта в индексе | Есть хотя бы одна проверяемая цифра или измеримый факт — не «сделал агента», а «59 fps на iPhone 11» |
| F4 | Системный промпт интервьюера, собранный `PromptLibrary` | Плейсхолдер заменён, в тексте встречается название непрофильного проекта (например Lash Try-On) — то есть знание реально доехало до промпта |
| F5 | Живая сессия с Генри | Задаёт вопрос про проект, отличный от LinkBuilder, и называет его цифру так, как она измерена |
| F6 | Любая цифра в профиле | Прослеживается до источника: замер по репозиторию с датой либо явная ссылка на аудит человека (ошибочный вход — число без происхождения) |

## Non-functional

- Профиль на английском: он идёт в промпт англоязычного интервьюера.
- Никаких персональных контактов (телефон, email, Telegram) в промпте: агенту
  для интервью они не нужны, а промпт уезжает в логи сессий.
- Новых зависимостей нет.

## Оракулы

- **F1–F3** — тест в `backend/tests/`, читает файл знания.
- **F4** — тест на `PromptLibrary.interviewer_system()`.
- **F5** — живая сессия (ручной оракул, вне CI).
