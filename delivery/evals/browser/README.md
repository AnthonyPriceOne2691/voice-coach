# Браузерный оракул приёмки

Ручной стенд: настоящий Chromium, настоящая страница приложения, настоящий
голосовой тракт (whisper.cpp → qwen2.5 → Piper → SQLite). Имитируется **только
источник звука**.

```bash
delivery/evals/browser/run.sh --help     # что умеет и что ему нужно
delivery/evals/browser/run.sh mid-turn   # закрыть вкладку посередине хода
delivery/evals/browser/run.sh tabs       # History и Useful Words, снимки
delivery/evals/browser/run.sh all
```

Снимки и профиль браузера кладутся в `out/` рядом (gitignored).

## Зачем он есть

Нашёл **три** дефекта, которых не видел ни один зелёный гейт:

| Что нашёл | Чем это было незаметно |
|---|---|
| разрыв посередине хода не завершал сессию | тесты рвали соединение в состоянии ожидания — штатным путём |
| History и Useful Words не работали 38 дней | сборка не исполняет dev-прокси, юнит-тесты ходят в замоканный fetch |
| по History не отличить закрытую сессию от брошенной | данные в API были, показывать их было некому |

## Почему микрофон подменяется в странице

Штатный флаг Chromium `--use-file-for-fake-audio-capture` **в этой сборке
отдаёт цифровую тишину** — замер: трек `Fake Default Audio Input`,
`readyState: live`, `muted: false`, `AudioContext: running`, но `peak_rms 0`,
`−180 dBFS`. Поэтому `stand.py` подменяет `getUserMedia` потоком из
`AudioContext`: страница получает реплику, синтезированную Piper.

Всё, что ниже микрофона, настоящее: VAD страницы, `MediaRecorder`, WebSocket по
doc 15, whisper, LLM, TTS, запись в SQLite.

## Почему его нет в CI

Нужны Chromium, ollama с моделью, whisper.cpp и голос Piper. На раннере он был
бы вечно пропущенным — а пропущенный оракул хуже отсутствующего: он выглядит
как проверка (урок **L3** в `delivery/archive/INDEX.md`). Поэтому запуск ручной,
но воспроизводимый: `run.sh` проверяет предпосылки и **называет нехватку
словами**, а не падает трассировкой.

## Чего стенд НЕ проверяет

- Качество распознавания и синтеза — реплика заранее синтезирована, дикция
  идеальная. Настоящий микрофон в шумной комнате ведёт себя иначе.
- Другие браузеры: только Chromium.
- Вёрстку на узких экранах — окно фиксированное.
- Реальные тайминги latency-инварианта: для них есть
  `scripts/spike/benchmark_turn.py`.

## Как читать результат

`stand.py` печатает JSON: `verdict`, состояние последней сессии из API и её
транскрипт. Главное поле — `newest.ended_at`: непустое означает, что уборка
дошла до конца. `tabs.py` печатает текст с экрана и кладёт снимок.
