# Spec — contour-bootstrap-1.61

> ⚠ **Написана ПОСЛЕ факта, подписи не получала.** Bootstrap шёл по пошаговому
> устному согласованию (выбор из двух вариантов с ценой: «сначала блокер» против
> «сначала обновление»). Спека восстановлена по сделанному, чтобы `delivery_check`
> судил артефакт, а не пустоту. Помечать её подписанной было бы ровно тем
> расхождением учёта с действительностью, которое эта же поставка занесла в
> `archive/INDEX.md` уроком L1, — поэтому `human_ok_spec: deferred`, а не `yes`.

## Задача

Обновить развёрнутый контур `cqg@1.7 · delivery@1.11 · okf@1.5` до
`cqg@1.61 · delivery@1.48 · okf@1.12`.

## Почему это поставка, а не «обновление файлов»

Замер до старта: **ни один из 21 скрипта не совпадал байт-в-байт**, восемь
отсутствовали целиком. То есть перевыкладывание, а не патч.

## In scope

1. Все скрипты контура из Приложений канонов + обе копии канонов (`docs/canon/`
   и `Prepare/` — вариант C держит две) + `SHA256SUMS`.
2. Конфиги: `.pre-commit-config.yaml` (канон дословно + своё поверх),
   `backend/pyproject.toml` (bandit-правила, комплексити в ignore под гейт со
   снимком, `norecursedirs`, `[tool.mutmut] source_paths`).
3. Снимки всех правил, включая новые (`blind-error`, `unstructured-log`,
   `cpu-in-async`, `unbounded-list`, `complexity`, `deps-audit`).
4. Инструменты гейтов — в манифест, не мимо него.

## Out of scope

- **Висящий `test_ws_voice.py`** — блокер припаркованной `phase-2-acceptance`.
  Переезжает в спеку следующей поставки. Причина порядка: диагностировать вис на
  контуре 1.61 дешевле — там судит мутационный гейт и `filterwarnings=["error"]`
  ловит незакрытые ресурсы, типичную причину таких висов.
- **Апгрейд `vitest` до 4.x** (semver-major) — решение человека, `escalation.md`.
- **`filterwarnings = ["error"]`** — канон предписывает порядок внедрения: включить,
  прогнать сьют целиком, внести чужие предупреждения поштучно. Внутри bootstrap'а
  это смешало бы два источника поломок. Отдельной поставкой, вместе с висом.

## Acceptance examples

id — одна заглавная латинская + цифра, читается из первой колонки. Все пять
**замерены**, а не предсказаны: колонка «Факт» заполнена по прогону.

| id | Вход / условие | Ожидаемый выход | Факт |
|---|---|---|---|
| A1 | `contour_doctor.py` на чистом env | `DEAD 0` | `DEAD 0` ✓ |
| A2 | тот же прогон, счёт непробованного | `SKIP <= 1` | `SKIP 1` (`check_canon_vendor.sh` — своё, канарейки нет) ✓ |
| A3 | `pre-commit run --all-files` при ПОЛНОСТЬЮ чистом env | 0 провалов из 28 | 0 провалов ✓ |
| A4 | `cpu-in-async-gate` при чистом env, `--verbose` | непустое число просмотренных | «просмотрено 45 файл(ов), в снимке 2» ✓ |
| A5 | `pytest -q` в `backend/` | все проходят, покрытие >= 85% | 91 passed, 93.51% ✓ |

Почему A3 и A4 сформулированы через «чистый env»: до этой поставки гейты брали
дефолт `backend/features`, каталога с таким именем в проекте нет, и они печатали
«0 файлов просмотрено» с кодом 0 — сводка показывала `Passed`. Проверять надо
именно в тех условиях, в которых хук запускается на коммите, а не в удобных.
