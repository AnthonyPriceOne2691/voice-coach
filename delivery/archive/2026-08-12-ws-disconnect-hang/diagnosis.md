# Diagnosis: вис прогона на ubuntu при отключении клиента без `end_session`

**Симптом (дословно, CI и локальный Linux-контейнер):** прогон не заканчивается;
`pytest-timeout` печатает

```
File ".../starlette/testclient.py", line 708, in __exit__
File ".../anyio/from_thread.py", line 560, in start_blocking_portal
    thread.join()
+++++++++++++++++++++++++++++++++++ Timeout ++++++++++++++++++++++++++++++++++++
```

и убивает **процесс**, то есть красным становится весь прогон, а не тест.

## Воспроизведение — сначала оно, потом гипотезы

Локально на macOS: **0 висов из 60** (замер предыдущей поставки). Это и держало
дефект: воспроизводить было негде, кроме CI по 6 часов.

Linux-контейнер (`python 3.12.13`, aarch64) с тем же сьютом:
**6 висов из 10 прогонов**. Цикл диагностики стал 40 секунд.
Значит различие — не «ubuntu против macOS» вообще, а раскладка планировщика и
пула соединений на Linux; сам дефект платформенно-независим и на macOS просто
редко проявляется.

## Журнал гипотез

| # | Гипотеза | Как проверял | Вердикт |
|---|---|---|---|
| H1 | `_warmup_task` (`asyncio.create_task`, никем не отменяется) остаётся висеть | Дамп незавершённых задач в момент `_cancel_all_tasks` | **ОТВЕРГНУТА.** Задача в дампе одна, и это не warmup. Фейки STT/LLM мгновенные, warmup успевает завершиться. Но задача-сирота реальна и чинится заодно — см. «что правим», п.2 |
| H2 | Гонка `flow.finish()` в `on_disconnect()` с `db.dispose()` из lifespan | Чтение кода + дамп | **ЧАСТИЧНО ВЕРНА.** Гонка есть, но виснет не запись и не `dispose`, а их последствие — см. H3 |
| H3 | Соединение остаётся ВНЕ пула, и SQLAlchemy добивает его задачей, которой цикл ждёт | Патч `asyncio.runners._cancel_all_tasks`, печать незавершённых задач | **ПОДТВЕРЖДЕНА** |

## Подтверждённая причина

В момент закрытия цикла незавершённая задача **ровно одна**:

```
-> <coroutine object AsyncAdapt_aiosqlite_connection._terminate_graceful_close>
   File ".../sqlalchemy/dialects/sqlite/aiosqlite.py", line 347,
        in _terminate_graceful_close
     await self._connection.close()          # future, который уже никто не разрешит
```

Рядом — предупреждение самого SQLAlchemy:

```
SAWarning: The garbage collector is trying to clean up non-checked-in connection
<AdaptedConnection <aiosqlite.core.Connection ...>>, which will be terminated.
Please ensure that SQLAlchemy pooled connections are returned to the pool explicitly
```

Цепочка целиком:

1. Тест выходит из `with ... as ws` при ЖИВОЙ сессии, не послав `end_session`.
2. Сервер получает `WebSocketDisconnect` -> `on_disconnect()` -> `flow.finish()` ->
   репозиторий пишет статус через `async with self._db.session()`.
3. Одновременно `TestClient.__exit__` гасит приложение: портал **отменяет**
   задачу обработчика. Отмена приходит внутрь `async with`, а выход из контекста
   сам требует `await` (rollback/release) — довести его отмена не даёт.
4. Соединение остаётся не возвращённым в пул. Позже его подбирает GC, SQLAlchemy
   заводит `_terminate_graceful_close`, а `asyncio.runners.close()` при закрытии
   цикла делает `run_until_complete(gather(*to_cancel))` и **ждёт эту задачу
   вечно**: разрешить future некому — рабочий поток `aiosqlite` уже не крутится.

**Почему через раз:** всё решает, успеет ли запись завершиться до прихода отмены.
Отсюда 6 из 10, а не 10 из 10, и отсюда же ноль на macOS, где планировщик
раскладывает эти два события иначе.

**Почему это не дефект теста.** Тест делает законное: клиент может отвалиться
без `end_session` в любой момент — браузер закрыли, сеть пропала. Инвариант
«отключение клиента завершает сессию» принадлежит продукту, а не сьюту; сьют его
лишь исполняет. Красный прогон целиком (а не один тест) — цена того, что дефект
живёт в пути завершения.

## Что правим (по убыванию важности)

1. **Уборка сессии не должна отменяться на полпути.** Работа `on_disconnect`
   выполняется под защитой от отмены и с таймаутом: соединение обязано вернуться
   в пул при любом исходе.
2. **`_warmup_task` — задача-сирота.** Создаётся двумя путями, не отменяется
   нигде. Здесь она не виновата, но это тот же класс: владелец обязан её закрыть.
3. **Гашение приложения обязано дождаться живых ws-сессий** до `db.dispose()` —
   иначе п.1 закрывает окно, но не дверь.
