# Spec: выбор микрофонного устройства

## Problem

`useVoiceSession.start()` открывает микрофон вызовом `getUserMedia({ audio: true })` —
то есть **системный по умолчанию**, каким бы он ни был. Это единственная строка
таблицы Settings в doc 17, оставшаяся с крестиком с 2026-06-26.

Почему это не косметика:

1. **Системный дефолт меняется сам.** macOS переключает вход при подключении
   гарнитуры, наушников с микрофоном, монитора с камерой. Пользователь узнаёт об
   этом не из интерфейса, а по внезапно испортившемуся распознаванию.
2. **Порог VAD −50 dBFS откалиброван под конкретный тракт** (doc 15). Другой
   микрофон — другой уровень: слишком тихий вход не переступит порог, и Генри
   будет молчать, «не слыша» ответа. Со стороны это выглядит как поломка агента,
   а не как выбор устройства.
3. **Обойти нечем.** Ни настройки, ни конфига, ни переменной окружения нет —
   единственный способ сменить вход сейчас — системные настройки macOS, которые
   меняют его для всех приложений сразу.

## In scope

- Строка **Microphone** на экране Settings: выпадающий список входных устройств,
  первый пункт — `System default`.
- **Имена устройств требуют разрешения**: до гранта `enumerateDevices()` отдаёт
  устройства с пустым `label`. Экран показывает не пустой список, а приглашение
  выдать доступ с кнопкой; после гранта список наполняется именами.
- **Хранение** — новый kv-ключ `mic_device_id` (`string | null`, `null` =
  системный по умолчанию) там же, где остальные четыре настройки. `PATCH` с
  чем-то, кроме строки или `null`, отвечает 422 — как коридор темпа.
- **Использование**: `start()` открывает поток с `deviceId: { exact: <id> }`,
  когда ключ задан.
- **Отказ выбранного устройства виден.** Устройство отключили — `getUserMedia`
  бросает `OverconstrainedError`; сессия продолжается на системном по умолчанию
  **и говорит об этом**. Молчаливый `{ ideal: … }`-фолбэк запрещён по той же
  причине, по которой темп отвечает 422, а не зажимается.
- **`devicechange`**: пока экран Settings открыт, список пересобирается при
  подключении/отключении железа.
- **Проверка уровня** (решение человека, 2026-08-15): кнопка `Test` открывает
  выбранный вход и показывает живой уровень существующим `MicLevelMeter` — с
  отметкой порога VAD и словами «hearing you / silent». Выбрать вход вслепую и
  узнать о его тихости на середине интервью — ровно тот отказ, который поставка
  и должна закрыть. Поток держится только пока идёт проверка.
- doc 15 (пятый ключ настроек), doc 17 (строка становится ✅).

## Out of scope

- **Выбор устройства вывода** (динамики/наушники) — doc 17 его не обещает,
  а браузерный `setSinkId` — отдельная механика.
- **Автовыбор «лучшего» микрофона** — эвристика без оракула.
- **Смена устройства на живой сессии** — микрофон открывается один раз на старте
  (echo-защита завязана на цикл воспроизведения). Настройка применяется со
  следующей сессии.

## Риски

- **`deviceId` не вечен.** Он «солёный»: привязан к origin и профилю браузера и
  меняется при очистке данных сайта. Сохранённый id тогда перестанет находиться —
  это ровно случай M5, и он должен быть **видимым**, а не тихим.
- **Разрешение запрашивается вне сессии.** Чтобы показать имена, экран Settings
  открывает поток — треки надо гасить сразу же, иначе индикатор записи в macOS
  останется гореть на экране настроек.
- **Проверить полностью может только человек.** jsdom не имеет устройств: тесты
  проверяют вызовы к подменённому `navigator.mediaDevices`, а то, что звук
  реально идёт с выбранного входа, подтверждается живым прогоном (M9).
